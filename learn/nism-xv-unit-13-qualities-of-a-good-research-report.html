Key terms, examples and exam traps

Report structure

A good report has a clear recommendation, summary, business overview, financial analysis, valuation, risks and disclosures.

Example. A report opens with the rating and the key reasons.

Exam trap. This statement is false: A report need not state a recommendation.

Recommendation and rating

A rating such as buy, hold or sell must be defined, with the basis stated, and applied consistently.

Example. A report defines buy as an expected return above 15% over twelve months.

Exam trap. This statement is false: Ratings can be undefined labels.

Target price

A target price is the analyst's estimate of a security's price over a stated horizon, backed by a valuation method and assumptions.

Example. An analyst sets ₹500 with a twelve-month horizon using a P/E method.

Exam trap. This statement is false: A target price needs no supporting valuation.

Risk disclosure in reports

A report should state the key risks to its thesis, so readers understand what could go wrong.

Example. A report lists regulatory changes and input costs as risks.

Exam trap. This statement is false: Reports should hide risks to appear persuasive.

Clarity and objectivity

Clear language, supported claims and balanced treatment of positives and negatives make a report credible.

Example. A report cites sources for each figure.

Exam trap. This statement is false: A good report uses exaggerated claims.

Reasonable basis

Every recommendation must have a reasonable basis supported by research and data, not mere speculation or rumour.

Example. An analyst bases her call on filings and a valuation model.

Exam trap. This statement is false: A recommendation can rest on market rumours.

Timeliness and updates

Reports should be updated when material events occur and should state the date and data cut-off.

Example. An analyst revises the target after the quarterly results.

Exam trap. This statement is false: A report never needs revision after publishing.

Data sources and accuracy

Sources should be reliable and cited, and numbers cross-checked for accuracy.

Example. An analyst verifies figures with filings.

Exam trap. This statement is false: Data need not be checked before publishing.
